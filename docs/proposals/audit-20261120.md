> 盤查（2026-11-20），只讀資料，沒有改程式、沒有呼叫付費 API。資料是 `postlaunch/20261120` 上的 1,211 筆上架紀錄（sec.v2 全量重掃後、規則 1 還沒套），本機帳本 `~/.pickfit/ledger.sqlite`、watch 主機的帳本（11/18 起）、Cloud Run 上 11/18–19 的 matcher log，以及 `loop/issues.md`。重算指令：`uv run pickfit coverage report`、`uv run pickfit coverage tasks`、`uv run pickfit security --gaps`。

## 1. 驗證卡點

### 先看結論

- 軟體自己壞掉的很少：安裝失敗 12 筆（tool_fault 11、failed 1），功能因軟體自身錯誤失敗 10 筆。
- 其餘沒驗到的，幾乎都是 pickfit 的環境、harness 或流程還沒做到，或是合理的限制（付費、實體硬體）。
- 平均驗證比例 66%。最弱的是網頁 App（37%）、`other` 類別（41%）、`local_ai`（59%），以及 Swift（45%）和 C/C++（48%）生態系。

### tokens 提案落地了多少

- **T1**（預設 Opus）、**T2**（第一輪就快取）、**T5-2**（judge 的輸出只送一次）：已經在 main。
  - watch 主機到盤查時還在舊程式，所以帳本看不到效果。等它自動更新後要再量一次。
- **T3 Batch API**：模組和翻譯、使用說明兩個呼叫端已經在 main，但兩邊帳本裡 batch 筆數都是 0，還沒真正跑過。watch 主機的帳本也還是舊格式，沒有 `batch` 欄位和 `boxes` 表。

## 3. 安全審查覆蓋

### 現在的覆蓋率

全部 1,211 筆，含 11/18 後新增的 64 筆。

| 覆蓋 | 筆數 | 佔比 |
|---|---|---|
| complete | 759 | 62.7% |
| partial | 202 | 16.7% |
| unchecked | 250 | 20.6% |

### 沒審完的 452 筆卡在哪

一筆可能有好幾個原因。

| 原因 | 筆數 | 說明 |
|---|---|---|
| `adapter.missing` | 109 | Maven 51、Swift 45、NuGet 17 等，讀不了這些生態系 |
| `advisory_db.no_ecosystem` | 103 | C/C++，OSV.dev 沒有這個生態系的資料 |
| 依賴解析失敗（`resolve.pyproject_failed` 87、`registry_failed` 33） | 120 | 多半是 Python |
| 沒有 lockfile（`lockfile.missing` 68、`none_found` 66） | 134 | |
| `source.none` | 50 | 網頁 App 沒有公開原始碼 |
| `lockfile.unsupported_format` | 45 | bun.lock 39、yarn.lock 22 |
| `binary.prebuilt_package` | 41 | 套件裡是預先編好的 binary |
| `platform.sbom_unsupported` | 37 | macOS 的 SBOM 還不支援 |

### 新沙盒映像跑起來之後

新映像有 syft、govulncheck、cargo-audit。

- **可以補上的 155 筆。** 這些紀錄的缺口，全都能靠「Linux 上裝好的東西」的 SBOM 補上，而且它們已經有通過的 Linux 安裝。
  - 原因分布：Maven、NuGet、Pub 這類 adapter 26 筆；沒 lockfile、解析失敗、lockfile 格式不支援、預編 binary 的組合佔其餘。
  - 補上之後，complete 從 759 變成 914，62.7% → 75.5%。
- **但這 155 筆要重新驗證才會產生 SBOM**，因為 SBOM 只在 replay 箱子裡收。
  - 整筆重驗：約 155 × US$0.25 ≈ US$40。
  - 更便宜的做法：做一個「只重跑安裝並收 SBOM」的指令，照紀錄裡存好的安裝步驟在新箱子裡重播，不呼叫模型。每筆只有幾分錢的 Modal 費用，合計約 US$2–5。這個指令還沒有，是安全覆蓋這條線投報率最高的工作。
- **另外 82 筆也能靠 SBOM 補，但還沒有通過的 Linux 安裝**，要先解決第 1 節的卡點。

### 再往上推，下一塊補什麼

剩下的大多不是 SBOM 能解決的：

1. **C/C++，97 筆以上。** OSV.dev 沒有這個生態系。可以用 syft 找出 vendored 的函式庫，再用 NVD 的 CPE 比對（例如 grype 的資料庫）。補上之後大約 +8%。
2. **網頁 App 沒原始碼，50 筆。** 只能做被動檢查，例如前端引用的 JS 函式庫版本（retire.js 這類）。大約 +4%。
3. **macOS 的 SBOM 和 Swift，37＋30 筆左右。** 要有 Mac 主機，排在 H-012 之後。
