## 主要建議：不用裝新工具，用 git 內建的 word diff，但把「字」當成比對單位

git 預設是以空白切詞，中文段落沒有空白，所以整段被當成一個詞，才會整行紅綠。只要告訴 git 以單一字元為單位，就能看出改了哪幾個字。假設你是在終端機裡看 diff，且 git 版本是近幾年的（`--word-diff-regex` 早就支援）。

**安裝：** 不需要。`git` 已經足夠。

**第一次試用（在專案目錄執行，只讀不改檔案）：**

```bash
git diff --word-diff=color --word-diff-regex=.
```

每個字元都是獨立單位，改動的字會以紅字標出，前後沒改的字保持原樣。缺點是英文單字也會被拆開。

**建議再設成別名，方便日後使用：**

```bash
git config --global alias.wdiff '!git diff --word-diff=color --word-diff-regex="[A-Za-z0-9_]+|."'
```

這個版本讓英文和數字維持整字（例如 `git`、`v2.3`），中文仍以單字比對。之後用 `git wdiff` 即可。`git show`、`git log -p` 也可以加上同樣的 `--word-diff-regex` 參數。

**第一次執行的檢查方式：** 隨便改一段中文，執行 `git wdiff`，看到只有改動的字標成紅綠，就表示設定成功。

## 長期更好的做法：一句一行（每句換行）

Markdown 渲染時，句子中間的單一換行通常不影響顯示，而且 **每句一行** 的好處是：
- 任何 diff 工具（包括 GitHub 網頁、VS Code、`git diff` 原生輸出）都只會標出改動的那一句，不需要特殊設定。
- 在 code review 時更容易看出哪一句被改。

缺點是要把既有文件重新斷句，一次性工作量較大。如果要做，我可以幫你寫一個依 `。！？` 斷句的小腳本，但在執行前會先給你看內容，不會直接改檔案。

- 想立刻解決：用上面的 `git wdiff` 別名（不需安裝任何東西）。
- 想根本解決：文件改成一句一行。
