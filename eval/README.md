# 評測：題組與評分方式

題目在 [questions.yaml](questions.yaml)。這份說明和題目在**同一個 commit** 凍結，凍結時間就是那個 commit 的時間。

## 1. 這份評測要回答什麼

同一個 AI agent，**接上 pickfit 之後**，推薦的軟體是不是比它自己上網查**更符合使用者的條件、裝得起來、第一次執行就成功**；在該說「內建的就夠了」的時候，有沒有誠實說。

## 2. 題目怎麼來的

- 2026-10-28（比賽期間）新寫，沒有使用賽前的評測草稿。
- 由 AI agent 起草：3 個 agent 各從一個角度起草（使用者情境、知名工具不符條件的情況、誠實與涵蓋度），共 42 題；1 個 agent 挑出 20 題；3 個 agent 分別從公平性、可量測性、真實性審查；最後 1 個 agent 依審查修改定稿。念誠逐題審定後凍結。
- 題目只寫需求與可檢查的條件，**不寫預期答案**。
- 組成：開發者 CLI 工具 10 題、本地 AI／LLM 工具 10 題；找軟體 14 題、找替代品 4 題、「內建就夠」2 題；繁體中文 5 題；可在 Linux 容器驗證 17 題、只能在 Mac 驗證 3 題（q08、q11、q12）。

## 3. 凍結與防止照題目準備資料

- 凍結後**不改題目與檢查項目**。唯一允許的修改是「對任何答案都壞掉」的測試資料或檢查腳本：要在任何一組開跑前 commit 並寫明原因，兩組一起套用。勘誤寫在本文第 9 節。
- **建資料的 session**（發現、抽取、驗證、計分）**不讀 `eval/`**；只有評測執行與評分讀。讀過題目的 session 不寫 discovery 的 query。
- discovery 的 query 依類別寫，不從題目推導；每條 query 連同時間記在 trace。
- 檢查項目裡寫「at freeze」「pre-freeze」的測試資料、固定模型、版本，指的是**第一次開跑評測前 commit**（測試資料凍結）。題目與檢查項目本身在今天凍結。

## 4. 組別與執行方式

| 組別 | agent | 可用工具 |
|---|---|---|
| 對照組 | Claude Code 無頭模式 | WebSearch、WebFetch |
| 實驗組 | 同一版本 | WebSearch、WebFetch、pickfit MCP |
| rules-only（選做） | 同一版本 | 同實驗組，但 pickfit 關掉模型配對 |

- 三組用同一個 Claude Code 版本、模型、設定；版本記在結果裡。
- **隔離**：每題在空的暫存目錄執行，用 `--strict-mcp-config --mcp-config <檔案>`（對照組空的、實驗組只有 pickfit），不載入這台電腦使用者層級的其他 MCP（例如 toolradar）。不給 Bash、Edit、Write 等本機工具。
- 只送題目的 `prompt`，其他欄位只給評分者看。每題前面加同一段開場：`Recommend only; do not run commands or change files on this machine. If something is unclear, state your assumption and answer anyway. Put your main recommendation first and include install and first-run steps.`
- 單回合、不追問。**每題每組跑 1 次**（時間與預算限制；雜訊照實寫在結果裡）。各組在同一個 24 小時內跑完。pickfit 的程式與資料版本固定，記下 commit。
- 花費：先跑 2 題估單題花費；Anthropic 評測總花費上限 $30。

## 5. 評分

**評哪一個推薦**：第一個推薦，或答案明確標為首選的那個。若答案說另一個選項「一樣好」而它違反硬條件，L1 不過。

**三層檢查**（每個檢查項目都標了層級）：

| 層 | 意思 | 怎麼查 | 範圍 |
|---|---|---|---|
| L1 | 推對軟體：存在，且符合每個硬條件 | 查官方 repo、文件、授權 | **20 題全做** |
| L2 | 裝得起來、跑得動 | 照答案的步驟在乾淨環境實跑 | 先做「安裝＋第一次執行」，再做題目裡的進階檢查；兩組**依題號順序**做，做不完的兩組都標「未實跑」 |
| L3 | 該說「內建就夠了」時誠實說 | 讀答案 | q10、q20 |

- 「內建就夠」題：主要答案必須是內建做法，額外工具要標成選用，否則記 `unneeded_install`。
- 「找替代品」題：推薦繼續用現在的工具，只有每個檢查都過才算對。
- 答案寫了自訂腳本：題目允許寫程式時，只評 L2；題目排除寫程式時（q06），L1 不過。
- 答案說「沒有任何工具符合全部條件」：只有在全部跑完後，另開一個不接 pickfit 的 agent session 搜尋，念誠再自己搜尋 30 分鐘，都找不到通過 L1 的選項時，才算對。

**評分者可以做的調整**：填入版本號與佔位字、接受安裝程式預設值；Ubuntu 擋下裸 `pip install` 時改在 venv 裡跑（記 `needed_venv`，但「照步驟原樣成功」那一項不過）。**不可以**：修正錯的指令或旗標、補上缺的步驟、換掉答案指定的模型。

**執行環境**：
- Linux：Modal Sandbox（x86_64，和產品驗證同一套），image 以 `ubuntu:24.04` 為底，記下 image digest。安裝 20 分鐘、每個檢查 10 分鐘逾時。
- Mac（q08、q11、q12）：念誠的 Apple silicon Mac，用另開的 macOS 使用者帳號，每次跑完照清單移除裝過的東西。由念誠親手執行（`method: human`）。

**判讀模型輸出的檢查**（q11、q15、q16 等）：能固定 temperature 或 seed 就固定；不能就跑 3 次、2 次過算過。繁簡判斷用固定版本的 OpenCC（逐字判斷，繁體比例 ≥0.95 且至少 30 個繁簡不同字）。需要判斷語意時，用固定版本的 Claude 模型、固定評分說明，看不到組別。

**盲測偏好**：每題把兩組的答案去掉可辨識組別的字（pickfit、工具名換成 `[source]`），隨機排成 A／B；念誠在看到任何檢查結果前選 A、B 或平手，附一句理由。偏好和客觀結果並列，不覆蓋客觀結果。

**長尾標記**：推薦的工具 GitHub 星數 <1,000，或第一次公開發布在評分日前 18 個月內，就標長尾。只報告，不算輸贏。

## 6. 事先決定的難度分組

依「對照組自己找」的預期難度事先分組，避免事後挑題：

- 容易（不退步檢查）：q03、q04、q07、q08、q12、q13、q19、q20。實驗組在這組不應該比對照組差。
- 中等：q02、q05、q06、q09、q10、q14、q15、q17、q18。
- 困難：q01、q11、q16。
- **主要結果**：中等＋困難 12 題的通過率。20 題的完整結果一律並列。
- 相似題群（一筆資料可能同時影響幾題，報告時註明）：mcp-tooling（q01、q06）、local-openai-endpoint（q12、q13、q14、q20）、local-model-client（q18、q19）、traditional-chinese-output（q11、q15）。

## 7. 報告

README 列出每一題兩組的結果，**包括輸的題與兩組都沒過的題**；附逐字答案（原始與去識別版）、檢查紀錄、版本資訊。並寫明：

- 題目由 AI 起草、念誠審定並凍結；出題者與 pickfit 的開發者是同一個人（個人參賽）。
- 每題只跑 1 次。
- L2 實跑到第幾題、哪些題「未實跑」。
- q18、q19 是問某一家廠商的 agent，推薦跟該廠商無關的工具，所以也在測中立性。

## 8. 檢查項目裡的測試資料

各題 `success_checklist` 提到的測試資料（設定檔、log 產生器、CSV、PDF／DOCX、OpenAPI 規格、測試伺服器、音檔、文件夾等）在第一次開跑前 commit 到 `eval/fixtures/`。假的金鑰、token 在執行時產生，不 commit。q15 的音檔用 CC0 授權的公開中文錄音（念誠 2026-10-28 決定），附逐字稿與來源。
